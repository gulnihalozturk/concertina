# Concertina — implementation, benchmark and verification scripts

This repository accompanies the paper *Concertina: A Birthday-Bound Secure
Tweakable Variable-Length Wide-Block Mode* by Gülnihal Öztürk, Onur Koçak and
Oğuz Yayla.

Concertina is a tweakable wide-block mode (hash-encrypt-hash) whose two-block
head is a four-round Feistel network. Encryption and decryption use only the
forward direction of the block cipher, and no finite field multiplication is
required. The instantiation uses AES, HMAC-SHA3-256 (or HMAC-SHA-256) and the
NIST SP 800-108 key derivation.

| Paper | Files |
|-------|-------|
| Sect. 2, specification | `src/scheme.c` (C), `python/scheme_ref.py` (independent reference) |
| Sect. 2.2, design minimality (Table 2) | `attacks/distinguishers.py` |
| Sect. 4, performance (Table 3) | `src/bench.c`, measurement in `results/apple-m4/` |
| Appendix A, microcontrollers (nRF52840, nRF52832) | separate repository: [concertina-nrf52](https://github.com/gulnihalozturk/concertina-nrf52) |

## 1. Verify the distinguishers of Table 2

Requires Python 3 and the `cryptography` package.

```sh
pip install cryptography
python3 attacks/distinguishers.py            # HMAC-SHA3-256, 200 trials
python3 attacks/distinguishers.py --hash sha256
```

For each simplified variant V1–V6 (and V6 with an encrypted counter seed),
the distinguisher is run against the variant and against the full
construction. Expected output: the relation holds in every trial for the
variant and in no trial for Concertina. The script first checks that its
implementation of the full construction agrees with the reference
implementation.

## 2. Run the benchmark (Apple silicon or AArch64 Linux)

Requires a C compiler (on macOS: `xcode-select --install`).

```sh
make test       # self-tests
make bench      # self-tests + benchmark -> results/results.csv, results/table.tex
```

On an x86-64 Linux machine, the self-tests can be run under QEMU (the
benchmark figures would be meaningless there):

```sh
sudo apt-get install gcc-aarch64-linux-gnu libc6-dev-arm64-cross qemu-user
make CC=aarch64-linux-gnu-gcc
qemu-aarch64 -cpu max -L /usr/aarch64-linux-gnu ./concertina-bench --selftest
```

Options: `./concertina-bench --sizes=32,64,256,512,1024,4096 --ntries=15
--target-bytes=2097152 --keybits=128|256 --freq-ghz=X --outdir=results
--no-portable --selftest`

All modes (Concertina, HCTR2 and AES-XTS as a narrow-block reference) share
one AES implementation based on the ARMv8 Cryptographic Extension, so that
the measured differences come from the modes themselves. The "portable" rows
keep the AES instructions but compute POLYVAL, Keccak or SHA-256 without
dedicated instructions.

Apple silicon does not expose a cycle counter to user programs; cycles per
byte are computed from wall-clock time and the core frequency, measured
before and after the run with a chain of dependent single-cycle additions
(a warning is printed if the frequency changes by more than 3%). Each value is
the best of `--ntries` runs. On macOS, the benchmark requests the highest QoS
class so that it runs on a performance core.

## 3. Validation

Before benchmarking, every component is checked:

* AES: FIPS 197, Appendix C;
* SHA-3, SHA-256 and HMAC: known answers from Python's `hashlib`/`hmac`, all
  message split points, and the SHA-3-instruction Keccak-f against the
  portable one on random states;
* POLYVAL (96), XCTR (180) and HCTR2 (700) vectors from the official HCTR2
  repository, for both POLYVAL backends;
* AES-XTS: known answers from Python `cryptography`;
* Concertina: 90 known answers from `python/scheme_ref.py` (both hash
  functions, AES-128/192/256, lengths from 32 to 1000 bytes, also in place).

`make kat` regenerates `src/kat_generated.h` from the reference implementation.

## Encoding

The implementation is byte-oriented. The two-bit role codes of the paper
(`10`, `01`, `00`) are encoded as the octets `0x02`, `0x01`, `0x00`, each
directly followed by the 16-byte tweak:

    X_P = H(Pbar || 0x02 || T),   X_C = H(Cbar || 0x01 || T)

Counter block `i` is `E(S xor <i>_128)` with a big-endian counter starting at
0. The working keys are `K_u = MSB_k(H_KM(<1>_32 || "concertina/u" || 0x00 ||
<k>_32))` for `u` in `{1, 2, 3, 4, ctr, hash}`.

## Files

* `src/aes.c` – AES key schedule, counter mode and XCTR
* `src/polyval.c`, `src/hctr2.c` – POLYVAL (PMULL and constant-time portable) and HCTR2
* `src/keccak.c`, `src/keccak_round.inc` – Keccak-f[1600] (SHA-3 instructions
  and portable), SHA3-256, HMAC-SHA3-256; the round function is generated by
  `tools/gen_keccak_round.py`
* `src/sha256.c` – SHA-256 (SHA-2 instructions and portable), HMAC-SHA-256
* `src/scheme.c` – Concertina, including key derivation
* `src/xts.c` – AES-XTS reference
* `src/selftest.c`, `src/kat_generated.h` – self-tests and known answers
* `src/bench.c` – benchmark driver with CSV and LaTeX output
* `python/scheme_ref.py` – independent reference implementation, KAT generator
* `attacks/distinguishers.py` – distinguishers of Table 2
* `results/apple-m4/table.tex` – the measurement reported in the paper
